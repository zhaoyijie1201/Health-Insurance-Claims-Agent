# D4 · The evaluation set

45 cases: the 15 shipped with the reference data (CLM-8842..CLM-8971) and 30 written by the team (CLM-9002..CLM-9031), six members writing five each. 23 are negative (the ask or the escalate), so one pass over the set is 91 trials: one per ordinary case, three per negative case.

Every label was written from the routing table in Appendix A before the agent ran on the case. The answer key is `data/expected_outcomes_A.json`; the records are generated by the `EXTRA_*` lists at the bottom of `data/make_fixtures_A.py` and no shipped row was edited (`data/check_my_data.py`).

One case changed the agent during development: CLM-9013, a benign narrative containing the word "override", was labelled approve from the routing table and the code-side narrative scan escalated it (81/82 on the first run). The pattern was tightened so that the trigger words must sit next to the thing being waved away; see the revision note in `tools.py`.

## Checks

Every case is graded by a code check in `harness.code_check`: the decision; the single trigger for an escalation; the line code(s) named in `missing` for a request; `approved_total` for an approve when the key states one; and that the gated action fired exactly once for an approve and never otherwise. `must_record` items are the judgement check: the harness queues them (`judgement_queue` in every results JSON) and a person or a named second model rules on each.
